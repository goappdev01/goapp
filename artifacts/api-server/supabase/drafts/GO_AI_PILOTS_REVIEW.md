# GO IA para pilotos: dependencias antes de activar

Estado del código: la conversación central sigue limitada a ADMIN validado en cliente y servidor. El proveedor está desactivado salvo que Railway configure `GO_CENTRAL_AI_ENABLED=true`, `OPENAI_API_KEY`, `GO_CENTRAL_AI_MODEL`, `GO_CENTRAL_AI_MAX_OUTPUT_TOKENS` y `GO_CENTRAL_AI_REQUESTS_PER_MINUTE`. La voz requiere además `GO_CENTRAL_AI_TRANSCRIPTION_ENABLED=true` y un modelo de transcripción. Ninguna clave pertenece a Expo o GitHub. La ruta no ejecuta herramientas y envía a OpenAI solo los mensajes que el usuario autoriza en esa sesión, con `store:false`.

El historial local optativo permanece. El historial entre dispositivos se ofrece únicamente si el servidor anuncia `GO_CENTRAL_AI_HISTORY_ENABLED=true`. La interfaz exige una elección aparte, conserva copia local mientras sincroniza, no restaura consentimiento de envío a OpenAI y requiere confirmar la sustitución de un chat local diferente. El servidor usa el JWT del usuario, el ADMIN verificado y una revisión optimista para impedir sobrescrituras silenciosas. El cuerpo guarda hasta 20 mensajes y 12.000 caracteres. El borrado del chat escribe un historial vacío; comprobar la confirmación del servidor antes de afirmar que se eliminó remotamente.

**No desplegar el SQL de este directorio sin autorización específica.** Antes de activar el historial, obtener y restaurar en entorno aislado una copia actual del proyecto Supabase correcto; revisar la tabla y RLS de `go_ai_conversations_v1.sql`; registrar la migración con el procedimiento vigente; probar con dos identidades ADMIN y una no ADMIN, sesiones caducadas, acceso cruzado, conflictos de revisión, borrado y reinicio. Definir plazo de retención y tratamiento de solicitudes de supresión antes de un piloto. El esquema preparado se limita a ADMIN; ampliar la IA a EMPRESA o USUARIO exige un control de acceso y tratamiento de datos expresamente aprobados.

Después de autorizar esquema, proveedor y gasto, desplegar el servidor y comprobar su SHA real. Habilitar el historial y el modelo por separado; verificar respuesta auténtica, tokens y latencia de cada llamada, continuidad con dos dispositivos, voz solo si está habilitada y errores sin contenido privado en registros. La respuesta API informa métricas numéricas sin texto conversacional. El coste se calcula con tokens de entrada/salida multiplicados por las tarifas del modelo elegido; no hay estimación numérica fiable sin modelo, límites de piloto y tráfico previstos. El cliente Metro y MAIN por sí solos no activan la IA del servidor.
